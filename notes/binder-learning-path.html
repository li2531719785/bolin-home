Bolin Lab/笔记/Binder 学习路线

Android 系统开发的
Binder 学习路线

这条路线面向 Android 系统开发、Framework / Native / Kernel 方向，不教 App 开发。AIDL 只作为进入 Binder 协议的入口；主线是系统服务、libbinder、驱动和排障。

2026.11.17学习路线约 12 分钟系统开发 / 18 章

这份路线不是一份“Binder API 大全”，而是一条从系统服务到内核实现的教学顺序。目标是让做 Android 系统开发、Framework、Native 或 Kernel 的读者，最终能画出完整调用链、读懂关键源码，并且知道遇到问题该去哪里查。

!
读者定位：面向系统开发，不教 App 开发。AIDL 只用来进入协议层；重点放在系统服务、libbinder、Binder 驱动、SELinux 和排障。
!
先记住一句话：Binder 不是一个函数调用，而是一套跨进程对象访问机制。handle 在客户端，node 在服务端，transaction 和 buffer 负责把一次调用送过去。

模块 0 · 预备知识

第 0 章：听不懂 Binder，通常不是 Binder 的问题

先把这些前置知识补齐：进程与线程、虚拟内存、文件描述符、系统调用、ioctl、mmap。然后知道 Android 里 zygote、system_server 和普通 app process 的分工。

  • 理解“用户态 / 内核态”和一次系统调用的成本。
  • 知道 /dev/binder 是一个字符设备。
  • 能说清楚进程隔离为什么让普通函数调用无法直接跨进程。

完整展开： 第 0 章：Binder 的预备知识。里面有进程 / 线程、虚拟内存、fd、ioctl / mmap、Parcel、Android 进程模型、实验和自测题。

模块 1 · 建立直觉

第 1 章：Android 为什么需要 Binder

先从 RPC 的四步流程出发：定义服务、注册、获取代理、transact 调用；再解释“一次拷贝”是怎么来的。然后对比 pipe、socket、共享内存、信号，讲 Binder 的性能、安全、对象语义、引用计数和死亡通知。

这一章要解释“一次拷贝”说法的边界，但不要陷入内核细节。读者只需要先建立：Binder 是为 Android 的进程模型和对象模型量身定制的 IPC。

完整展开： 第 1 章：Android 为什么需要 Binder。包含 RPC 四步、一次拷贝路径、Linux IPC 对比、对象引用和适用边界。

第 2 章：Binder 的心智模型

用一张图讲清 Client / Server、Proxy / Stub、handle、Parcel、同步调用和 Binder 线程。示例用 IServiceManager.checkService("activity")，不写 App。

实验：不写代码，手画一次 shell service 命令调用 servicemanager 的完整链路。

完整展开： 第 2 章：Binder 的心智模型。从一次系统服务查找出发，讲清 Proxy / Stub、handle / node、Parcel、同步调用、Binder 线程和 4 个常见误解。

模块 2 · 系统服务与 AIDL

这一模块不写 App：先用系统命令和服务源码跑通一次真实调用，再看 servicemanager 的注册与用户态对象模型。

第 3 章：第一个 AIDL

不写 App，直接用系统自带的 service 命令调用 IServiceManager，看 AIDL 生成的 Proxy / Stub、Parcel 读写顺序、事务码，以及真机上的 Binder 线程和 /dev/binder 映射。

完整展开： 第 3 章：第一个 AIDL。包含 AOSP 源码锚点、真实 service call 输出、进程 / 线程 / 映射证据和练习。

第 4 章：系统服务里的 AIDL

以 servicemanager 为样本，看 Parcelable、in/out/inout、oneway、callback 和 DeathRecipient 在 AOSP 系统服务里怎么用；不写 App，直接读 ServiceManager.cpp、IActivityManager.aidl、IPackageManager.aidl。

完整展开： 第 4 章：系统服务里的 AIDL。包含 ServiceDebugInfo 真机实验、方向标签、oneway 生成代码、注册回调和 servicemanager 的死亡清理。

第 5 章：ServiceManager 与服务注册

按 servicemanager 的三个场景走：启动与 BINDER_SET_CONTEXT_MGR、addService 注册、getService / listServices 获取，以及和 hwservicemanager 的分工。callback 和 DeathRecipient 已在第 4 章展开。

整理中：本章正文暂时下线，后续按“源码 + 真机实验 + 时序图”的标准重写。

第 6 章：用户态 Binder 对象模型

把 IBinder、BpBinder、BBinder、Java 的 Binder 和 BinderProxy 放在一起讲。重点解释本地对象和远程代理的区别，以及为什么同一个服务在不同进程里 handle 可以不同。

模块 3 · Framework 与 Native 层

第 7 章：Framework 层：Binder 与 SystemServer

按 Java 层的三个场景走：Binder.java / BinderProxy / Parcel 的初始化，SystemServer 如何注册系统服务，以及客户端如何通过 ServiceManager.getService 获取代理并发起调用。

第 8 章：Native Binder（libbinder）

先写一个最小 native client（defaultServiceManager → checkService → transact），再拆 ProcessState、IPCThreadState、BpBinder、BBinder、Parcel 和 talkWithDriver，最后用 JNI 把 Java 层和 Native 层接起来。

第 9 章：一次调用的全链路

把前八章串成一条线：

AIDL Proxy
  → BinderProxy
    → JNI
      → libbinder / IPCThreadState
        → ioctl(BINDER_WRITE_READ)
          → Binder driver
            → server thread
              → Stub
                → 实际方法

这一章要回答：同步调用为什么阻塞调用线程、服务端线程池怎么接活、嵌套调用和线程池耗尽分别会发生什么。

模块 4 · 进入内核驱动

第 10 章：Binder 驱动的入口

/dev/binder、binderfs、open / mmap / ioctl，以及 binder_proc、binder_thread、binder_alloc、binder_device 和 binder_context 的角色。

第 11 章：核心数据结构与关系

这是整个路线里最需要图的一章：binder_proc 的四棵红黑树、两条队列和一个分配器；binder_node 与 binder_ref 的双向登记；binder_transaction、binder_buffer 与 binder_work 的连接。

可以配合 《Android Binder 驱动数据结构关系》 的交互图来讲。

第 12 章：一次事务的完整生命周期

从 BC_TRANSACTION 开始，走完 handle → ref → node、目标 buffer 分配、work 入队、BR_TRANSACTION、BC_REPLY、BR_REPLY 和 BC_FREE_BUFFER。最后对比同步与 oneway，解释 transaction_stack。

第 13 章：引用计数、死亡通知与生命周期

讲清 ref->data.strong / weak、node->internal_strong_refs、local_*、tmp_refs，以及 owner 进程死亡后 node 如何变成 dead node、客户端如何收到 BR_DEAD_BINDER。

第 14 章：并发、优先级与异常边界

锁顺序、线程池耗尽、嵌套调用死锁、优先级继承、Binder freeze、oneway spam、fd 传递、TransactionTooLargeException 与 BR_FAILED_REPLY。

模块 5 · 实战与进阶

第 15 章：Binder 调试与排障

使用 dumpsys、binder debugfs、Perfetto 和日志定位问题。把“客户端、服务端还是驱动出问题”变成可以逐步排除的流程，而不是靠猜。

第 16 章：安全与系统集成

UID / PID、SELinux、binder context、AIDL HAL、stable AIDL、system / vendor 分区与权限检查。知道 Binder 不只是 IPC，也是 Android 安全边界的一部分。

第 17 章：Capstone 实战

选一个真实系统服务（servicemanager 或 ActivityManagerService），追踪它的注册、调用和死亡清理；补 oneway / callback 的原生观察，最后画出客户端 → libbinder → 驱动 → 服务端 Binder 线程的全链路图。不写 App。

第 18 章：知识串联与高频问题

用高频问题检查理解：handle 是全局的吗？node 存在哪？为什么同步调用会阻塞？buffer 属于谁？一次调用为什么会有两笔 transaction？

课时不够时，压缩成三条路线

目标章节大概课时
系统服务开发 / 排障第 0–6 章 + 第 9、15 章9–11 章
Framework / Native 深入第 0–15 章15 章左右
完整讲透，包括驱动第 0–18 章 + 附录18 章主课

教学上最重要的三个建议

  1. 用一个系统服务贯穿全程。建议选 servicemanager 或 ActivityManagerService；每讲一层，就回到它，看它在 Framework、Native 和驱动里分别长什么样。
  2. 不要按源码文件顺序讲。先讲一次调用怎么发生，再解释沿途遇到的结构，而不是从 binder_internal.h 第一行开始念。
  3. 每章都让读者画图。能画出 Client → Proxy → Binder → Driver → Stub → Server 和 handle → ref → node，基本就讲懂了。
