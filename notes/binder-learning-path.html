给 Android 新手的
Binder 学习路线

给 Android 新手讲 Binder，建议 18 章主课 + 1 章预备 + 5 个附录。不要一上来讲 binder_proc 和红黑树，新手会当场放弃。正确顺序是：先会用，再懂框架，最后进内核驱动。

2026.11.15学习路线约 12 分钟18 章主线

这份路线不是一份“Binder API 大全”，而是一条从使用到实现的教学顺序。目标是让一个只写过 Android 应用的新手，最终能画出完整调用链、读懂关键源码，并且知道遇到问题该去哪里查。

!
先记住一句话：Binder 不是一个函数调用，而是一套跨进程对象访问机制。handle 在客户端，node 在服务端，transaction 和 buffer 负责把一次调用送过去。

模块 0 · 预备知识

第 0 章：听不懂 Binder，通常不是 Binder 的问题

先把这些前置知识补齐：进程与线程、虚拟内存、文件描述符、系统调用、ioctl、mmap。然后知道 Android 里 zygote、system_server 和普通 app process 的分工。

  • 理解“用户态 / 内核态”和一次系统调用的成本。
  • 知道 /dev/binder 是一个字符设备。
  • 能说清楚进程隔离为什么让普通函数调用无法直接跨进程。

完整展开： 第 0 章：Binder 的预备知识。里面有进程 / 线程、虚拟内存、fd、ioctl / mmap、Parcel、Android 进程模型、实验和自测题。

模块 1 · 建立直觉

第 1 章：Android 为什么需要 Binder

从 Linux 已有 IPC 出发：pipe、socket、共享内存、信号各自解决什么问题，又为什么不够。然后讲 Binder 的设计目标：性能、安全、面向对象语义、引用计数和死亡通知。

这一章要解释“一次拷贝”说法的边界，但不要陷入内核细节。新手只需要先建立：Binder 是为 Android 的进程模型和对象模型量身定制的 IPC。

第 2 章：Binder 的心智模型

用一张图讲清 Client / Server、Proxy / Stub、handle、Parcel、同步调用、oneway 和线程池。可以先用“寄快递”比喻：进程是邮局，handle 是取件码，node 是收件人，transaction 是包裹。

实验：不写代码，手画一次“App 调用系统服务”的完整链路。

模块 2 · 先会用 Binder

第 3 章：第一个 AIDL

写接口、Service、绑定和客户端调用，看 AIDL 自动生成的 Proxy / Stub，确认调用发生在哪个进程。先让新手跑通一次真实的跨进程调用，比背概念有效得多。

第 4 章：AIDL 进阶

基本类型、Parcelable、in/out/inout、oneway、callback、DeathRecipient、线程规则，以及常见坑：oneway 不能有返回值、回调可能不在主线程、跨进程对象需要正确 parcel。

第 5 章：ServiceManager 与服务注册

讲 addService / getService、为什么 handle 0 是特殊的、system_server 如何暴露系统服务，以及 servicemanager 和 hwservicemanager 的分工。

第 6 章：用户态 Binder 对象模型

把 IBinder、BpBinder、BBinder、Java 的 Binder 和 BinderProxy 放在一起讲。重点解释本地对象和远程代理的区别，以及为什么同一个服务在不同进程里 handle 可以不同。

模块 3 · Framework 与 Native 层

第 7 章：Java Binder Framework

从 Binder.java、BinderProxy、Parcel 和 ServiceManager 往下走，看 bindService 到 AMS 的流程，以及 SystemServer 如何注册服务。

第 8 章：Native Binder（libbinder）

讲 ProcessState、IPCThreadState、BpBinder、BBinder、Parcel 和 talkWithDriver，最后用 JNI 把 Java 层和 Native 层接起来。

第 9 章：一次调用的全链路

把前八章串成一条线：

AIDL Proxy
  → BinderProxy
    → JNI
      → libbinder / IPCThreadState
        → ioctl(BINDER_WRITE_READ)
          → Binder driver
            → server thread
              → Stub
                → 实际方法

这一章要回答：同步调用为什么阻塞调用线程、服务端线程池怎么接活、嵌套调用和线程池耗尽分别会发生什么。

模块 4 · 进入内核驱动

第 10 章：Binder 驱动的入口

/dev/binder、binderfs、open / mmap / ioctl，以及 binder_proc、binder_thread、binder_alloc、binder_device 和 binder_context 的角色。

第 11 章：核心数据结构与关系

这是整个路线里最需要图的一章：binder_proc 的四棵红黑树、两条队列和一个分配器；binder_node 与 binder_ref 的双向登记；binder_transaction、binder_buffer 与 binder_work 的连接。

可以配合 《Android Binder 驱动数据结构关系》 的交互图来讲。

第 12 章：一次事务的完整生命周期

从 BC_TRANSACTION 开始，走完 handle → ref → node、目标 buffer 分配、work 入队、BR_TRANSACTION、BC_REPLY、BR_REPLY 和 BC_FREE_BUFFER。最后对比同步与 oneway，解释 transaction_stack。

第 13 章：引用计数、死亡通知与生命周期

讲清 ref->data.strong / weak、node->internal_strong_refs、local_*、tmp_refs，以及 owner 进程死亡后 node 如何变成 dead node、客户端如何收到 BR_DEAD_BINDER。

第 14 章：并发、优先级与异常边界

锁顺序、线程池耗尽、嵌套调用死锁、优先级继承、Binder freeze、oneway spam、fd 传递、TransactionTooLargeException 与 BR_FAILED_REPLY。

模块 5 · 实战与进阶

第 15 章：Binder 调试与排障

使用 dumpsys、binder debugfs、Perfetto 和日志定位问题。把“客户端、服务端还是驱动出问题”变成可以逐步排除的流程，而不是靠猜。

第 16 章：安全与系统集成

UID / PID、SELinux、binder context、AIDL HAL、stable AIDL、system / vendor 分区与权限检查。知道 Binder 不只是 IPC，也是 Android 安全边界的一部分。

第 17 章：Capstone 实战

做一个包含 callback 和 DeathRecipient 的 AIDL 服务，观察线程池，抓一次完整调用链，最后画出从 App 到内核驱动的全链路图。

第 18 章：知识串联与面试

用高频问题检查理解：handle 是全局的吗？node 存在哪？为什么同步调用会阻塞？buffer 属于谁？一次调用为什么会有两笔 transaction？

课时不够时，压缩成三条路线

目标章节大概课时
Android 应用开发，会用 Binder第 1–6 章 + 第 9 章8–10 章
面试、系统开发、排障第 1–15 章15 章左右
完整讲透，包括驱动第 0–18 章 + 附录18 章主课

教学上最重要的三个建议

  1. 用一个 AIDL Demo 贯穿全程。每讲一层，就回到这个 Demo，看它在应用层、Framework、Native 和驱动里分别长什么样。
  2. 不要按源码文件顺序讲。先讲一次调用怎么发生，再解释沿途遇到的结构，而不是从 binder_internal.h 第一行开始念。
  3. 每章都让新手画图。能画出 Client → Proxy → Binder → Driver → Stub → Server 和 handle → ref → node，基本就讲懂了。
